This document is meant to be used as the guidelines for solving the current problem of memory-saving and search queries for search_recipes.
Since the model being used cannot run parallel calls, analyze if the following structured process is the most efficient way to achieve the desired outcome, or if there is a better structured process to solve this same issue.

Process idea:
-If the user states preferences without asking for a recipe, the agent should run only the save_user_preferences_tool. This tool must divide their results in two separate fields: "WANTS" and "DOES NOT WANT" and directly save their output to the "AI Short-Term Memory (Temporary)".
-If the user asks for recommendations, the assistant must ask the user for preferences in a prompt, without calling any tools yet.
-If the user states preferences AND asks for recommendations in the same message, The following should happen:
1. The agent calls for the save_user_preferences_tool and the search_recipe tools to happen SEQUENTIALY, not in parallel. (Is this possible?)
2. The save_user_preferences_tool must run first, saving their findings ONLY to "AI Short-Term Memory (Temporary)", as stated above.
(Is it possible to configure it so that it does not send their output BACK to the agent, which creates an additional LLM call, and instead only save the results as strings in the two separate fields saved in "AI Short-Term Memory (Temporary)"?)
3. The search_recipes tool then executes (as it was already queued), and it always reads as input the string contents of WANTS in "AI Short-Term Memory (Temporary)", and executes with any POSITIVE inferences extracted from there. NEGATIVE inferences ("Does not want) ideally will not be present in the WANTS field, because of the previous separation.
4. The LLM receives the output of ONLY the search_recipe tool, but additionaly reads as input the contents of the DOES NOT WANT field, and then cross-checks to see if any of the retrieved recipes should be crossed out because of the preferences stored in DOES NOT WANT.
5. If after the cross-search none of the initially retrieved recipes remain, it should run search_recipes again, but adding the crossed-out recipes IDs as EXCLUDED IDs. The excluded IDs should be accumulated. For that to work, either the the search_recipe tools must be updated to accept this EXCLUDED IDs as input (even if it is empty) or the excluded IDs must be filtered out deterministically before the search_recipe tools is executed (just like we do with missing appliances and dietary restrictions).
